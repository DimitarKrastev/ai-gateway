# Plan — AI Coding Gateway

## Cross-cutting decisions
- **Stack:** .NET 10 (SDK 10.0.103, pin via `global.json` with rollForward latestFeature), ASP.NET Core minimal APIs, SQLite (Microsoft.Data.Sqlite / EF Core), xUnit + `WebApplicationFactory` tests. Frontend: Vite + React + TypeScript + Recharts, in `web/`; production build is served by the backend as static files (SPA fallback). npm (no pnpm).
- **Layout:** `src/Gateway` (app), `src/Gateway.Fakes` (fake providers, runnable standalone), `tests/Gateway.Tests`, `web/`, `scripts/`, `AiGateway.sln`.
- **Ports:** gateway on `GATEWAY_PORT` (6200), Vite dev on `WEB_PORT` (6201), fakes/anything else in `AUX_PORTS` (6202-6219). Always check a port is free (`lsof -iTCP:<p> -sTCP:LISTEN`) before binding; never kill processes we didn't start. Tests use in-memory TestServer or ephemeral ports where possible.
- **Routing paths:** `/anthropic/*` → Anthropic (Claude Code: `ANTHROPIC_BASE_URL=http://localhost:6200/anthropic`). `/openai/*` → OpenAI API (`/openai/v1/responses`, `/openai/v1/chat/completions`) or, for ChatGPT-subscription accounts, the ChatGPT Codex backend (`/backend-api/codex/responses`). Upstream base URLs are configurable so tests/e2e point at fakes.
- **Client auth:** agents present a gateway client key (Claude Code: `ANTHROPIC_AUTH_TOKEN`/`x-api-key`; Codex: provider `env_key` → `Authorization: Bearer`). Gateway strips it and injects the linked account's credential: Anthropic API key → `x-api-key`; Claude subscription OAuth → `Authorization: Bearer` + `anthropic-beta: oauth-2025-04-20`; OpenAI API key → Bearer; ChatGPT subscription → Bearer access token + `chatgpt-account-id`. OAuth tokens are pasted (Claude `.credentials.json` / `claude setup-token`; Codex `~/.codex/auth.json`) and refreshed via a configurable token endpoint.
- **Secrets:** account credentials encrypted at rest (ASP.NET Data Protection, keys in data dir), never returned by the API. UI login with an admin password (env `GATEWAY_ADMIN_PASSWORD`, else generated on first start and written to the data dir file `admin-password.txt`). Data dir default `./data` (gitignored), overridable.
- **Sticky sessions:** session id derived from Claude Code `metadata.user_id` (`..._session_<uuid>`) or `x-claude-code-session-id` header; Codex `session_id`/`conversation_id` header or `prompt_cache_key`. Fallback: hash of client key + first user message. Session→account binding persisted.
- **Limits:** captured from response headers (Anthropic `anthropic-ratelimit-unified-*` 5h/7d utilization+reset, standard `anthropic-ratelimit-*`; Codex `x-codex-primary-*`/`x-codex-secondary-*`; OpenAI `x-ratelimit-*`) and from usage endpoints when available (Anthropic `/api/oauth/usage`, ChatGPT `/backend-api/wham/usage`). Generic model: account → list of limit windows {name, utilization %, resetsAt}.
- **Resets:** no public provider API known → modeled as a provider adapter capability (list reset credits with expiry; consume one) implemented by the fakes, plus manual add in the UI. Recorded as assumption in README.
- **Maximize utilization:** global setting. When on, choose among non-exhausted eligible accounts the one whose binding limit resets soonest; rebind sessions (cache miss accepted). If all exhausted, consume the reset closest to expiring and route to that account. When off: sticky, least-utilized for new sessions, failover only when exhausted.
- **Analytics data:** one row per request: time, provider, account, session, agent, model, input/output/cache-read/cache-write tokens, context size, tool calls, cost (pricing table), latency, status, stream flag. Agent = main vs subagent within a session (heuristic, documented); concurrency = overlapping in-flight requests/active agents.

## Work items (sequential, main tree)
1. **Scaffold** — solution, projects, global.json, frontend skeleton, static serving, config/ports, SQLite schema bootstrap, admin login, health endpoint, build scripts, .gitignore, README skeleton.
2. **Fake providers** — `Gateway.Fakes`: fake Anthropic (messages streaming/non-streaming, usage, tool_use, rate-limit headers, oauth usage, token refresh, resets) and fake OpenAI (responses + chat completions, ChatGPT codex backend, x-codex headers, wham usage, token refresh, resets). Controllable state (utilization, exhaustion). Standalone runnable.
3. **Accounts + proxy core** — linked account CRUD (encrypted), client keys, transparent streaming proxy for both providers, credential injection, token refresh, sticky sessions. Tests vs fakes.
4. **Usage capture + analytics API** — SSE/JSON usage parsing, tool calls, cost, context size, agents/concurrency, persistence, time-series & breakdown endpoints. Tests.
5. **Limits, resets, routing policy** — limit capture/refresh, resets list/use, maximize-utilization selection & rebinding, exhaustion fallback. Tests.
6. **Web UI** — login, overview, accounts (link/edit, limits, resets, use reset), settings, analytics graphs with breakdowns by account/session/agent/model.
7. **E2E + delivery** — e2e scripts simulating Claude Code and Codex traffic via fakes, browser check of UI, README completion, start/stop scripts, fresh-clone build+test, leave gateway running on 6200.

# Feature: OpenAI bridge (Claude Code → OpenAI models) — branch `feature/openai-bridge`

## Constraints
- Branch `feature/openai-bridge` (from `feature/tokens-per-second`); never touch `main`.
- Live instance on 6200 from `publish/` with real accounts in `data/`: never stop/restart/rebuild into it; never touch `publish/` or `data/`; never run `scripts/start|stop|restart.sh`.
- Ports 6300-6359 only (`AUX_PORTS=6300-6359 scripts/e2e.sh`), temp data dirs. Never call real providers; extend fakes.

## Cross-cutting decisions
- **Advertised id scheme:** default `anthropic-openai-<openai model id>` (e.g. `anthropic-openai-gpt-5-codex`), display name `<model display> (OpenAI)`. User-editable id + display name; id must match `/(claude|anthropic)/i` (Claude Code discovery filter), be unique, and contain only `[A-Za-z0-9._:-]`. Requests match the advertised id case-insensitively, ignoring a trailing `[1m]`-style suffix.
- **Code location:** `src/Gateway/Bridge/` (translator: `AnthropicToResponsesRequest`, `ResponsesToAnthropic` JSON + incremental SSE translator, `AnthropicErrors`; catalog/selection store, endpoints). Tests `tests/Gateway.Tests/Bridge*Tests.cs`.
- **Request translation (Anthropic → Responses):** system → `instructions` (text joined with "\n\n"; cache_control dropped); user text → `input_text`; image base64/url → `input_image` (data URL); PDF document → `input_file` (`file_data` data URL); assistant text → assistant message `output_text`; `tool_use` → `function_call {call_id=id,name,arguments=json}`; `tool_result` → `function_call_output {call_id, output}` (string, or array with `input_text`/`input_image` when images; `is_error` → text prefixed "Error: " if not already); tool results precede following user text. Previous `thinking` blocks whose signature carries our bridge envelope (`bridge1:` + base64url JSON `{id, encrypted_content}`) → `reasoning` item with `encrypted_content` (other thinking blocks dropped); `redacted_thinking` same if bridge-enveloped. Tools → `{type:function,name,description,parameters:input_schema,strict:false}`; Anthropic server tools (web_search_*, code_execution_*, etc.) dropped (limitation). tool_choice auto/any/tool/none → auto/required/{type:function,name}/none; `disable_parallel_tool_use` → `parallel_tool_calls:false` (else true). Effort: `output_config.effort` low/medium/high/max → low/medium/high/xhigh, clamped to the model's supported levels when the catalog knows them (else max→high); `thinking.budget_tokens` (when no effort) ≤4k→low, ≤16k→medium, else high; `thinking.type=disabled`/absent with no effort → no `reasoning.effort` (provider default). `reasoning.summary:"auto"` when thinking enabled/adaptive. Always `include:["reasoning.encrypted_content"]`, `store:false`. `metadata.user_id` session → `prompt_cache_key`. `speed:"fast"` → `service_tier:"priority"`. temperature/top_p/top_k/stop_sequences/cache_control/context_management/anthropic-beta dropped. `max_tokens` → `max_output_tokens` for API-key accounts only.
- **Codex backend (ChatGPT accounts) requirements:** `stream:true` always (non-stream client requests are aggregated from the stream), `store:false`, `instructions` non-empty, no `max_output_tokens`/temperature/top_p, `include` reasoning.encrypted_content, `parallel_tool_calls`, `tool_choice`, `prompt_cache_key`; headers `chatgpt-account-id` (existing injection), `OpenAI-Beta: responses=experimental`, `originator: codex_cli_rs`, `session_id: <session>`. The fake enforces these (400 otherwise).
- **Response translation:** reasoning item → `thinking` block (summary text; `signature` = bridge envelope), message `output_text`/`refusal` → `text`, `function_call` → `tool_use {id=call_id,name,input}`. Streaming: `message_start` (id `msg_<response id>`, model = advertised id, zero usage) → `ping` → blocks: thinking (`thinking_delta` from `reasoning_summary_text.delta`, `signature_delta` at item done), text (`text_delta`), tool_use (`input_json_delta` from `function_call_arguments.delta`; if none streamed, emit full args at done) with proper `content_block_start/stop` indices → `message_delta {stop_reason, usage}` → `message_stop`. stop_reason: function_call present → `tool_use`; incomplete max_output_tokens → `max_tokens`; content_filter → `refusal`; else `end_turn`. Usage: `input_tokens = input - cached`, `cache_read_input_tokens = cached`, `cache_creation_input_tokens = 0`, `output_tokens = output` (includes reasoning). `response.failed`/`error` events → Anthropic `event: error`. Upstream HTTP errors → Anthropic error JSON, status kept (400 invalid_request_error, 401 authentication_error, 403 permission_error, 404 not_found_error, 413 request_too_large, 429 rate_limit_error, 5xx api_error, 503/529 overloaded_error).
- **count_tokens** for bridged models: local estimate (≈ chars/4 of translated input), never calls the provider.
- **Model catalog:** OpenAI API key → `GET {OpenAIApi}/v1/models` (keep chat/reasoning-capable ids: gpt-*, o\d*, codex*, excluding audio/realtime/tts/transcribe/image/embedding/moderation/search-preview); ChatGPT → `GET {ChatGptBackend}/backend-api/codex/models?client_version=<ver>` (`{models:[{slug,display_name,description,supported_reasoning_levels,visibility,...}]}`). Merged per model with the accounts that list it; manual entries allowed. Refresh on demand from the UI (button) — never automatically against providers on startup beyond what the user triggers. Persisted in SQLite (append migration).
- **Routing:** bridged request routes with provider `openai` through the existing `IAccountSelector` (sticky by Claude Code session id, failover on 429, limits from upstream headers), restricted to OpenAI accounts that list the model when the catalog knows which do (manual models: any OpenAI account).
- **Models endpoint:** `GET /anthropic/v1/models` (client-key auth) returns the real Claude models (proxied from an Anthropic account if any is linked; on failure/no account, none) plus exposed OpenAI models `{id, type:"model", display_name, description, created_at}`, with `has_more:false`, `first_id`, `last_id`.
- **Analytics:** bridged rows: provider `openai`, account = the OpenAI account, `model` = actual OpenAI model (from response, else catalog), new column `requested_model` = advertised id, new column `bridge` = `anthropic->openai` (nullable for normal traffic); agent type/agents identified from the Anthropic request (Claude Code heuristics); usage/tps/speed parsed from the upstream Responses stream (existing OpenAI parser) so reasoning tokens and output speed work.
